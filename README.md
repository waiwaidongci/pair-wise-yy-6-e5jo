# 墨锭试磨批次与放行台

把墨锭试磨室重构为「试磨批次 + 放行台」，规则、存档、页面三层分离。

## 运行

```bash
npm start          # http://localhost:3037
npm test           # 21 项纯规则自测
```

数据保存在 `data/ink-stick-testing.json`（v2 结构）。旧版 v1 数据首次启动时自动迁移：墨锭档案保留，旧的 logs/tests 转入每锭的 `legacy` 只读留档，不占用批次号。

## 代码结构（规则 / 存档 / 页面分开）

| 文件 | 职责 |
| --- | --- |
| `rules.js` | 纯规则：批次开启、缺项作废、换人/4 小时/两次高分放行、低分重置、更正失效、状态推导。不读写文件、不发请求，时间由参数注入。 |
| `archive.js` | 存档：JSON 持久化、编号唯一、v1→v2 迁移。 |
| `page.js` | 页面：HTML/CSS 与浏览器交互，不含业务判定，状态一律取服务端推导结果。 |
| `server.js` | 仅 HTTP 装配与路由。 |
| `test-rules.js` | 纯规则自测（`npm test`）。 |

## 放行规则

1. **一锭一未结束批次**：每锭存在未结束批次时，不能开启新批次（接口返回 409）。
2. **六项登记缺一作废、不占号**：磨口、用水、纸样、室温、湿度、试磨人，外加评分；缺任一项，本次开启作废，记入该锭作废记录但不占用批次号。
3. **两次高分才放行**：评分 ≥ 85 为高分，当前连续高分计数达到 2 才可能放行。
4. **换人 + 隔 4 小时**：同一试磨人连续两次结果不能放行；复核必须换人（不得与当前连续高分链首条试磨人相同），且距上一次试磨满 4 小时。
5. **低分重置、记录留档**：任一低分立即把连续高分计数清零；所有结果原样保留。
6. **更正即失效**：更正已放行批次的关键字段（六项登记或评分）会使放行失效，批次标记「已失效」，并在批次履历中留档；失效后该锭可开启新批次。仅更正备注不影响放行。

状态不单独存储——墨锭状态（待试磨 / 试磨中 / 已放行 / 未放行）与批次状态（进行中 / 已放行 / 未放行 / 已失效）都由存档推导，因此列表、批次履历和刷新后状态始终一致。

联调时可用 `REVIEW_GAP_MS=0 npm start` 临时关闭 4 小时间隔。

## API

- `GET  /api/sticks` 墨锭列表（含批次、结果、履历，状态为推导值）
- `POST /api/sticks` 建档
- `POST /api/sticks/:code/batches` 开启批次（缺项返回 `{voided:true}`，不占号；有未结束批次返回 409）
- `POST /api/sticks/:code/batches/:no/results` 试磨/复核登记（缺项返回 `{invalid:true}`，不记入）
- `POST /api/sticks/:code/batches/:no/close` 结束批次（未放行）
- `PATCH /api/sticks/:code/batches/:no/results/:rid` 更正结果（关键字段更正会使已放行批次失效）
- `GET  /api/stats` 状态统计

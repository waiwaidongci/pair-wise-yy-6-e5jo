# 墨锭试磨室 · 试磨批次与放行台

把墨锭试磨室重做为「试磨批次 + 放行台」，规则、存档、页面三层分开：

| 文件 | 职责 |
| --- | --- |
| `src/rules.js` | 全部业务规则（纯函数）：缺项、连续高分、换人四小时放行、状态推算 |
| `src/store.js` | JSON 存档：读写、占号号码池、旧版数据迁移 |
| `src/page.js` | 单页界面：建档、登记、放行台、批次履历、更正表单 |
| `server.js` | HTTP 接线：路由与入参校验，不内联规则 |

## 运行

```bash
npm start        # http://localhost:3037
npm test         # 规则单元测试 + HTTP 端到端测试
```

数据保存在 `data/ink-stick-testing.json`（可用 `DATA_PATH` 环境变量覆盖）。旧版存档（`items[].logs/tests`）首次启动自动迁移：缺登记项的旧试磨记录转为作废留档批次，不占号。

## 规则

1. **未结束批次唯一**：每锭墨锭同时只能有一个进行中批次；存在未结束批次时开启新批次返回 `409`。批次进入已放行 / 已作废 / 已失效即为结束。
2. **登记六要素**：磨口、用水、纸样、室温、湿度、试磨人，另有 0–100 的评分；任一项缺失，该批次作废并结束，**号码回池复用（作废不占号）**，缺项内容仍写入该批次留档。
3. **放行条件**（每次登记后自动判定）：连续两次高分（评分 ≥ 85）；两次须为不同试磨人，且间隔满 4 小时；三个条件同时满足才自动放行。
4. **低分重置**：任一低分（< 85）把连续高分计数清零，需重新累计；所有旧记录保留在批次履历中。
5. **更正失效**：更正已放行批次的关键字段（六要素或评分，须填原因），该批次立即变为「已失效」，墨锭状态随之变为「放行失效」，更正前后的值与原因写入履历；失效后可另开新批次重新放行。
6. **单一状态来源**：墨锭状态（待试磨 / 试磨中 / 已放行 / 放行失效）不在存档中保存，列表、批次履历、刷新后均由 `rules.js` 从批次履历实时推算，保持一致。

## API

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/state` | 墨锭列表（含批次、记录、履历、放行判定）与统计 |
| `POST /api/items` | 墨锭建档（`code` 必填且唯一） |
| `POST /api/items/:id/batches` | 开启批次（有进行中批次时 409） |
| `POST /api/items/:id/batches/:bid/records` | 登记结果；缺项返回 `{voided:true,missing:[...]}`，放行返回 `{released:true}`；可带 `at`（ISO 或 datetime-local）指定登记时间 |
| `PATCH /api/items/:id/batches/:bid/records/:rid` | 更正关键字段（`reason` 必填）；已放行批次返回 `{invalidated:true}` |
